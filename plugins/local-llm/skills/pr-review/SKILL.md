# pr-review スキル: 他人のPRのプレレビュー(ローカルLLM)

PRの差分を自分(Claude)で最初から読む代わりに、まずローカルLLMにセキュリティ・品質観点で
一次レビューさせ、その結果を土台にする。手動実行用の `/pr-review` コマンドと同じスクリプトを使う。

## 実行手順

### 1. 前提確認

```bash
curl -s http://localhost:11434/api/tags
```

- 接続できない、または `gemma4:12b` が無い場合: このスキルをスキップし、その旨をユーザーに一言伝えて
  通常通り自分でレビューする(ブロッカーにしない)

### 2. 一次レビュー実行

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/pr_review.py <PR番号またはURL> [--repo owner/repo]
```

### 3. 結果の扱い

- 出力(要確認 / 参考)をそのままユーザーに提示する
- **high の指摘**: 差分を読んで妥当性を確認する。妥当ならレビューコメント案として採用、偽陽性なら理由を添えて除外する
- **low の指摘**: 参考情報として列挙するだけにする
- ローカルLLMが扱わない観点(仕様との整合・設計判断・テストの妥当性)は、ユーザーが求めた場合のみ自分で補う
- 指摘ゼロでも「ローカルプレレビュー: 指摘なし」と一言報告する

### 4. 投稿

ユーザーが明示的に「投稿して」と言った場合のみ、承認された内容で `gh pr review <番号> --comment --body "..."` を実行する。

## 注意

- 見逃しなく確認したい重要なPRでは `LOCAL_REVIEW_MODEL=qwen3.6:27b` を指定してよい(数倍遅い)
- 決定的ツール(linter / SAST)の代替ではない
