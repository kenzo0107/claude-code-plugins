# Go 一般セキュリティ・品質レビュー観点

外部入力(HTTPリクエスト、CLI引数、環境変数、ファイル、DB由来の値)が届き得る箇所を
特に注意して確認する。

## インジェクション

- SQL: クエリを文字列結合・fmt.Sprintf で組み立てていないか。プレースホルダ($1, ?)を使うこと
- OSコマンド: exec.Command に "sh -c" +変数、または引数への未検証の外部入力がないか
- パストラバーサル: filepath.Join にユーザー入力を渡してファイルを開く/配信していないか
  (filepath.Clean + プレフィックス検証、または fs.Sub / http.FileServer の適切な利用)
- テンプレート: html/template ではなく text/template でHTMLを生成していないか。
  template.HTML / template.JS への外部入力の混入

## SSRF・外部リクエスト

- ユーザー入力のURLへ http.Get 等でアクセスしていないか(内部ネットワークへの到達可能性)
- リダイレクト追従・スキーム・宛先の検証があるか

## 秘密情報

- APIキー・パスワード・トークンのハードコード
- 秘密情報や個人情報を log / エラーメッセージ / レスポンスに出力していないか

## 暗号・乱数

- パスワードハッシュに md5 / sha1 / 単純なsha256 を使っていないか(bcrypt / argon2 を使う)
- セキュリティ用途(トークン、セッションID)に math/rand を使っていないか(crypto/rand を使う)
- crypto/tls の InsecureSkipVerify: true
- 非推奨・弱いアルゴリズム(DES, RC4, ECBモード)

## 認証・認可

- 認可チェックの欠落: リソースIDを受け取る処理で「操作者がそのリソースの所有者/権限者か」の
  確認がないまま取得・更新していないか(IDOR)
- 認証程度の比較にタイミングセーフでない比較(==)を使っていないか(subtle.ConstantTimeCompare)

## 入力検証・リソース

- サイズ無制限の読み込み: io.ReadAll をボディに直接(http.MaxBytesReader 等の上限なし)
- zip/tar 展開時のパス検証(Zip Slip)
- ユーザー入力による無制限のゴルーチン生成・メモリ確保

## エラーハンドリング・並行処理(品質)

- エラーの握りつぶし(_ への代入、err を確認しない)
- defer での Close 漏れ(特にHTTPレスポンスボディ、ファイル)
- ゴルーチンからの共有変数への保護なし書き込み、ループ変数のキャプチャ
- context の未伝播(キャンセル不能な長時間処理)

## レビューの姿勢

- 差分(+行)に現れたコードのみ対象。既存コードの問題は指摘しない
- 「外部入力が届くか不明」な場合は confidence を low にし、その旨を issue に書く
- スタイルの好み・gofmt/リンタで検出できる事項は指摘しない
