# 一般コード品質レビュー観点(言語非依存)

言語別の観点ファイルが無いファイル(設定・シェル・SQL・YAML・Markdown 以外の一般コード)に使う。
セキュリティ観点は言語別ファイルが担うため、ここでは正しさと保守性に絞る。

## 正しさ

- 境界条件: 空配列・null/None・0・負数・最大値で壊れないか
- off-by-one、範囲の端の含む/含まない、整数除算・丸め
- 早期 return で後続の後処理(クローズ・ロック解放・状態復元)が飛ばないか
- 条件式の否定・and/or の優先順位の誤り、常に真/偽になる条件
- コピー&ペースト由来の変数名・キー名の取り違え(a を b にすべき箇所)
- タイムゾーン・ロケール・エンコーディングの暗黙依存

## エラーハンドリング

- 例外・エラー戻り値の握りつぶし、握りつぶした結果を後続が正常値として扱う
- リトライの無限ループ・バックオフ無し
- 部分失敗時の後始末(途中まで書いたファイル・DB の中間状態)

## 保守性

- 同じロジックの重複(既存関数で置き換えられる)
- マジックナンバー・文字列リテラルの散在
- 関数が長すぎる・責務が混在している(明らかに分割できる場合のみ)
- コメントとコードの不一致、嘘になったコメント・docstring

## 設定・スクリプト

- シェル: 変数の未クォート、`set -e` 下での `cmd | grep` による意図しない終了、`rm -rf "$VAR/"` で VAR 空の危険
- SQL マイグレーション: 大テーブルへのロックを伴う ALTER、NOT NULL 追加でデフォルト無し、ロールバック不能な変更
- YAML/JSON 設定: 環境ごとの値の取り違え(prd/stg)、シークレットの平文

## レビューの姿勢

- 差分(+の行)に現れたコードのみ対象。既存コードの問題は指摘しない
- 確信の無い指摘は confidence を low にする
- スタイルの好み・フォーマッタやリンタで検出できる事項は指摘しない
