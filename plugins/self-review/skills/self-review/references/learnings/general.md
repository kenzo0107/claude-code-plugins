## GEN-001: スキル横断のファイル参照は相対パスでなく明示パスで書く
- 分類: correctness
- 登録日: 2026-08-24
- 出典: self-reviewプラグイン作成時のplugin-validatorレビュー (kenzo0107/claude-code-plugins)

Claude CodeプラグインのSKILL.md内の相対パスは、そのスキルのディレクトリ基準で解釈される。
別スキル配下のファイルを `references/...` のような相対パスで参照すると実在しないパスになり、
読み込みに失敗するか誤ったファイルを探すことになる。スキルをまたぐ参照は
`${CLAUDE_PLUGIN_ROOT}/skills/<skill名>/...` 起点の明示パスで書く。

悪い例:
```markdown
選別した指摘を `references/learnings/README.md` のフォーマットに変換する
(実体は別スキル skills/self-review/ の配下にある)
```

良い例:
```markdown
選別した指摘を `${CLAUDE_PLUGIN_ROOT}/skills/self-review/references/learnings/README.md`
のフォーマットに変換する
```

## GEN-002: 外部由来テキストを通知やLLMプロンプトに埋め込む際は無害化する
- 分類: security
- 登録日: 2026-08-24
- 出典: medpeer-dev/peerx-id-terraform PR #304

ログ・エラーメッセージなど外部由来のテキストをSlack通知にそのまま埋め込むと、
`<!channel>` 等の特殊記法をログに出力させることで任意の相手へのメンションが可能になる。
LLMプロンプトに埋め込む場合も同様にログ経由のプロンプトインジェクションが成立する。
埋め込み前にメンション記法のエスケープ、インジェクションを想定したプロンプト分離を行う。

## GEN-003: 自動処理の失敗を握りつぶさず通知する
- 分類: operations
- 登録日: 2026-08-24
- 出典: medpeer-dev/peerx-id-terraform PR #304

通知や調査を担う自動処理自体が例外で落ちた場合(外部APIコール失敗など)に何も通知しないと、
「動いていないこと」に誰も気づけない。例外時もフォールバックの通知(エラー内容の送信、
DLQ、アラーム)を行い、失敗を可視化する。

## GEN-004: 外部APIのポーリングは成功以外の終端ステータスを明示的に処理する
- 分類: correctness
- 登録日: 2026-08-24
- 出典: medpeer-dev/peerx-id-terraform PR #304

非同期ジョブのポーリングで成功ステータスだけを判定すると、Failed / Timeout / Unknown などの
異常系終端ステータスのときにタイムアウトまでループし続け、コストがかかるうえ原因も分かりにくい。
APIが返しうる終端ステータスをドキュメントで確認し、異常系は即座にループを抜けてエラー処理する。

## GEN-005: 変数名は実際に格納される値と一致させる
- 分類: readability
- 登録日: 2026-08-24
- 出典: medpeer-dev/peerx-id-terraform PR #304

名前が示す内容と実際の値が食い違う変数(例: `LOG_GROUP_MAP` という名前でロググループ名でなく
ARNを格納)は、後続処理での取り違えバグの温床になる。値の実体に合わせて命名するか、
値を名前に合わせて変換して格納する。

## GEN-006: 時間窓の基準はトリガー時刻でなく対象事象の発生時刻にする
- 分類: correctness
- 登録日: 2026-08-24
- 出典: medpeer-dev/peerx-id-terraform PR #304

イベント駆動で「前後N分のログを調べる」ような時間窓を切るとき、イベントの発火時刻
(例: CloudWatchアラームの状態遷移時刻)は実際のデータ発生時刻より遅れる(評価期間の分など)。
発火時刻基準で窓を切ると対象外のログを取得してしまう。イベントペイロードに含まれる
元データの時刻(例: アラームの reasonData 内のデータポイント時刻)を基準にする。

## GEN-007: 相互に関係するハードコード値は揃えるか定数として一元管理する
- 分類: readability
- 登録日: 2026-08-24
- 出典: medpeer-dev/peerx-id-terraform PR #304

同じ対象を扱う数値が別々の箇所にハードコードされていると(例: 取得件数 limit 100 と
表示件数 50)、値の関係が意図的な差なのか不整合なのか読み手に伝わらない。
定数として一元管理し、意図的に差をつける場合はその理由をコメントで示す。

## GEN-008: 従量課金の処理を起動するトリガーは対象を明示的に限定する
- 分類: design
- 登録日: 2026-08-24
- 出典: medpeer-dev/peerx-id-terraform PR #304

LLM呼び出しなど従量課金の処理を自動起動する場合、トリガー条件が広すぎると
(例: 全アラームに反応するイベントパターン)意図しない大量実行でコストが膨らむ。
対象をタグ・命名・明示的なリストなどでオプトイン方式に限定できる設計にする。
